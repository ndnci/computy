# Languages and themes

The interface uses i18next, explicit React calls and bundled JSON catalogs. Supported languages are French, English, Spanish, Brazilian Portuguese, German, Italian, Dutch, Polish, Russian, Ukrainian, Turkish, Arabic, Hindi, Bengali, Urdu, Indonesian, Vietnamese, Thai, Korean, Japanese, Simplified Chinese, Traditional Chinese, Persian, Hebrew and Swahili.

`system` chooses the first supported system language, falling back to English. Regional variants map to a supported language; Traditional and Simplified Chinese remain distinct. Arabic, Urdu, Persian and Hebrew use a right-to-left layout. `Intl` formats dates, numbers, durations and quantities. Identifiers, hardware values and user-entered labels remain unchanged.

Preferences are persisted by the Rust engine and shared with the CLI. The interface's local cache supplies the initial render. The theme follows `prefers-color-scheme` by default and reacts to system changes. Choosing light or dark overrides that behavior until system mode is restored.

## Catalogs

- `src/locales/source.json`: French source messages.
- `src/locales/catalogs.json`: bundled catalogs for other languages.
- `src/locales/overrides.json`: prioritized editorial corrections, particularly navigation, actions and diagnostic states.
- `src/locales/messages/` and `loaders.mjs`: per-language catalogs loaded locally on demand.
- `scripts/localize-source.mjs`: text extraction; `--apply` is an initial migration, not an operation to repeat on already localized JSX.
- `scripts/generate-locales.py`: generation **during development**, offline after downloading the models.

Translations start from local machine translation using open [Argos Translate](https://github.com/argosopentech/argos-translate) models, [CTranslate2](https://opennmt.net/CTranslate2/) and their tokenizers. Traditional Chinese is derived from Simplified Chinese with OpenCC. Model versions and hashes are recorded in `scripts/locales-models.lock.json`.

Navigation, action and result labels have explicit corrections for every language. Long technical text remains a translation baseline that needs linguistic review; canonical engine measurements and states are independent of wording. Automated checks detect repeated generation artifacts and lost placeholders. Exported reports retain their original observations.

**Using Computy requires no translation model, Python installation or translation service.** Only the small generated catalogs ship with the application. Project documentation is maintained in English independently of the UI's source language and selected locale.

## Updating text

```bash
node scripts/localize-source.mjs
node scripts/locale-overrides.mjs
node scripts/maintenance-locales.mjs
node scripts/startup-locales.mjs
node scripts/cleanup-locales.mjs
# Also includes reviewed style labels through tray-style-locales.mjs
# Generate catalogs with local models and the documented Python environment
python scripts/generate-locales.py
node scripts/split-locales.mjs
npm test
```

The generator requires `ctranslate2`, `sentencepiece`, `sacremoses`, `subword-nmt` and `opencc-python-reimplemented`. Use an isolated development Python environment, such as a Python 3.12 container, with model caches in `/tmp/computy-models`. Generation calls no translation API and sends no user text or hardware information to third parties.
