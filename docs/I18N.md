# Langues et thèmes

L’interface utilise i18next, des appels explicites dans React et des catalogues JSON embarqués. Les langues proposées sont : français, anglais, espagnol, portugais du Brésil, allemand, italien, néerlandais, polonais, russe, ukrainien, turc, arabe, hindi, bengali, ourdou, indonésien, vietnamien, thaï, coréen, japonais, chinois simplifié, chinois traditionnel, persan, hébreu et swahili.

`system` choisit la première langue système prise en charge, puis l’anglais. Les variantes régionales sont ramenées à une langue proposée ; chinois traditionnel et simplifié sont distingués. Arabe, ourdou, persan et hébreu appliquent une disposition de droite à gauche. `Intl` formate dates, nombres, durées et quantités. Les identifiants, valeurs de matériel et libellés saisis par l’utilisateur restent des données d’origine.

Les préférences sont persistées par le moteur Rust et partagées avec la CLI. Le cache local de l’interface sert au premier affichage. Le thème suit `prefers-color-scheme` par défaut et réagit aux changements du système ; un choix clair ou sombre remplace ce comportement jusqu’au retour au mode système.

## Catalogues

- `src/locales/source.json` : messages sources français.
- `src/locales/catalogs.json` : catalogues embarqués des autres langues.
- `src/locales/overrides.json` : corrections éditoriales prioritaires, notamment navigation, actions et états de diagnostic.
- `src/locales/messages/` et `loaders.mjs` : catalogues répartis par langue, chargés localement à la demande.
- `scripts/localize-source.mjs` : extraction des textes ; `--apply` est une migration initiale, pas une opération à répéter sur du JSX déjà traduit.
- `scripts/generate-locales.py` : génération **pendant le développement**, hors ligne une fois les modèles téléchargés.

Les traductions ont une base automatique locale produite par les modèles ouverts [Argos Translate](https://github.com/argosopentech/argos-translate) avec [CTranslate2](https://opennmt.net/CTranslate2/) et leurs tokeniseurs. Le chinois traditionnel est dérivé du chinois simplifié avec OpenCC. Les versions et empreintes des modèles sont consignées dans `scripts/locales-models.lock.json`.

Les libellés de navigation, d’action et de résultat ont des corrections explicites pour toutes les langues. Les textes techniques longs constituent une base de traduction à améliorer par relecture linguistique ; les mesures et états canoniques du moteur restent indépendants de leur formulation. Les répétitions de génération et variables perdues sont recherchées automatiquement. Les rapports exportés conservent leurs observations d’origine.

**Aucun modèle de traduction, Python ou accès à un service de traduction n’est nécessaire pour utiliser Computy.** Seuls les petits catalogues produits sont livrés avec l’application.

## Mettre à jour les textes

```bash
node scripts/localize-source.mjs
node scripts/locale-overrides.mjs
# Inclut aussi les libellés relus des styles via tray-style-locales.mjs
# Générer les catalogues avec les modèles locaux et l’environnement Python documenté
python scripts/generate-locales.py
node scripts/split-locales.mjs
npm test
```

Le générateur nécessite `ctranslate2`, `sentencepiece`, `sacremoses`, `subword-nmt` et `opencc-python-reimplemented`. Utiliser un environnement Python de développement isolé, par exemple un conteneur Python 3.12, avec le cache des modèles dans `/tmp/computy-models`. La génération n’appelle pas d’API de traduction et n’envoie ni texte utilisateur ni données matérielles à un tiers.
